# 実装計画
ここは各ファイルの実装内容・実装計画を書いていきます。実装する際にはこのファイルの内容を読み込み、定義が曖昧な場合は実装せずにユーザーに確認をしてください。

## 生データの取得処理について
生データを集計するための処理であり、そのデータを使った可視化やデータの整形などは行いません。また、データの取得処理に関しては[new.definition.md](new.definition.md)を対象にします。
### 処理の流れについて
1. 事前処理
    - データの取得（事前にダウンロードしているファイルの読み込み)
    - 出力保存パスの読み込み(results/result.csv)
        - csvには集計した生データを保存（データを整形して結果を確認するには他の処理ファイルで行う）
2. modules/generate_grid_map.pyの中での実装
    - 各グリッドの頂点座標を計算し、各グリッドにidを割り振る
3. 集計処理
    - ゴールキックをしているデータを検索
        - 一番最初のデータから順番に確認していく（forで)
    - pass_type == "Goal Kick"になっているものがゴールキックに対応する
    - new.definition.mdを確認し、定義通りに処理
    - 相手の連続保持時間がT秒以上となる対象タッチでロストを確定する。位置は、その連続保持の最初のアクションの1つ前の自チームのアクションの最終位置を記録する
    - 相手の保持時間をリセットしたら、位置の参照元も選び直す。判定確定時刻と位置の参照元を区別する
    - 自チームが一度も触れていなければ、T秒判定のロスト位置は相手の連続保持開始位置とする
    - 自チームの対象タッチ後の相手GK確保は、直前の自チームのアクションの最終位置を記録する
    - 両チームの対象タッチ0回での相手GK直接確保とダイレクトアウトは別集計し、右側ヒートマップの分母から外す。両チームの対象タッチ回数もCSVに保存する
    - 観測期間の上限は設けない。ただしシュート・オウンゴール・再開・GK確保・ダイレクトアウトでは定義通りに終了する（自チームのシュート・再開・GK確保は保持で終了）
    - ゴールキックが落ちた位置を事前に取得したグリッドの頂点座標と照合し、どのidに当てはまるかを取得 
4. 結果保存処理
    - csvファイルに書き込み
    - カラムは
        - id（元データから取得した順番に割り当て）
        - グリッドid（どこのグリッドに落ちたか)
        - 保持/ロスト
        - 保持/ロストの詳細説明（シュートの場合にはshotなど)
            - 決着前にハーフ終了、もしくは終了した場合はこのカラムに文字列として内容を記録
        - ロスト/保持の記録位置（自陣側をx=0として。時間判定によるロストは上記の自チームのアクションの最終位置、その他は各終了条件の位置）

## 実装ファイルと実行

- `modules/goal_kicks.py`：タッチ・終了条件・位置参照元を判定する。
- `scripts/analyze_goal_kicks.py`：保存済みデータを読み込み、`results/result.csv` に保存する。
- `modules/heatmaps.py`：着地点件数、着地点ごとの最終位置の件数・確率、欠損・除外件数を集計する。
- `scripts/view_goal_kicks.py`：CSVを読み込み、napariの左側に着地点件数、右側に選択グリッドの最終位置確率を表示する。
- 実行：`uv run python scripts/analyze_goal_kicks.py` → `uv run python scripts/view_goal_kicks.py`。
- 検証：`uv run python -m unittest discover -s tests -v`。
